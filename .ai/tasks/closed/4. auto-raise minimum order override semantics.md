## Context

Fitur ini dibuat untuk kasus exchange minimum order value, terutama Bybit `minimum order value 5 USDT`, ketika hasil sizing dari `riskPerTradePercent` terlalu kecil untuk lolos minimum notional exchange.

Goal utamanya:

- tetap pakai sizing berbasis margin USDT, bukan memaksa user berpikir dalam notional
- auto-raise qty hanya kalau memang diizinkan
- batas aman auto-raise ditentukan oleh `max margin` dalam USDT
- precedence override mengikuti level `global -> account -> channel`
- channel boleh override `ON` walaupun account di-set `OFF`

## Decision

Dipakai 2 setting baru:

- `autoRaiseMinOrderEnabled`
- `autoRaiseMinOrderMaxMarginUsdt`

Setting ini tersedia di:

- global risk settings
- account risk overrides
- channel risk overrides

## Override Semantics

### `inherit`

Pakai setting dari parent.

- di level account: parent = global
- di level channel: parent = account, lalu fallback ke global kalau account juga tidak set

### `enabled`

Paksa fitur auto-raise minimum order menjadi aktif di level itu.

Kalau level itu juga punya `autoRaiseMinOrderMaxMarginUsdt`, maka cap margin dari level itu yang dipakai.

### `disabled`

Paksa fitur auto-raise minimum order menjadi nonaktif di level itu.

Artinya walaupun parent `enabled`, level ini tetap menolak auto-raise.

## Effective Precedence

Urutan evaluasi:

1. Global default
2. Account override
3. Channel override

Contoh:

- Global `ON $0.50`, Account `inherit`, Channel `inherit` -> hasil akhir `ON $0.50`
- Global `OFF`, Account `enabled $0.40`, Channel `inherit` -> hasil akhir `ON $0.40`
- Global `ON $0.50`, Account `disabled`, Channel `inherit` -> hasil akhir `OFF`
- Global `ON $0.50`, Account `disabled`, Channel `enabled $0.30` -> hasil akhir `ON $0.30`

## Runtime Behavior

Sebelum submit order ke exchange, executor:

1. ambil `InstrumentSpecs`
2. baca `minNotional` exchange bila tersedia
3. hitung apakah `qty * price` masih di bawah minimum exchange
4. kalau iya:
   - raise qty ke minimum exchange bila fitur aktif dan required margin masih <= cap
   - reject lebih awal bila fitur nonaktif atau required margin > cap

Perhitungan cap selalu berbasis:

- `requiredMargin = requiredNotional / effectiveLeverage`

Bukan berbasis notional mentah.

## Reject Message

User memilih format reject yang eksplisit seperti ini:

`Trade rejected: exchange minimum requires margin $0.42 at 12x, but allowed auto-raise cap is $0.30`

Kalau balance bahkan tidak cukup untuk margin minimum exchange, executor boleh reject dengan pesan balance-based yang jelas.

## Logging Rule

Log error dari exchange tetap harus ada dan tidak boleh dihilangkan.

Perubahan yang diizinkan hanya menambah:

- log auto-raise minimum order
- log reject minimum order
- early reject message yang lebih jelas sebelum order dikirim

## Important Reminder For Future AI

- jangan ubah semantics `inherit / enabled / disabled` tanpa cek precedence override yang sekarang
- jangan ubah cap menjadi notional cap; cap yang disepakati adalah margin cap dalam USDT
- jangan hapus existing exchange logs; hanya boleh menambah log/reject context
- channel override `enabled` di atas account `disabled` adalah behavior yang disengaja
