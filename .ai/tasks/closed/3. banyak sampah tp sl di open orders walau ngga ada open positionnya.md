## Resolution

Bug source:

- orphan cleanup cron di `server/src/lib/orphan-cleanup-monitor.ts`
- tool `cleanup_orphan_protection_orders` di `server/src/lib/agent/tooling/position-ops-implementations.ts`

Keduanya sebelumnya masih mempertimbangkan `exchange.getOpenOrders()` sebagai sinyal bahwa sebuah symbol masih aktif.

Itu salah untuk kasus orphan TP/SL, karena:

- TP/SL/algo protection sendiri bisa muncul sebagai open order di exchange
- adanya pending/open order biasa dengan symbol yang sama tidak berarti protection lama masih valid
- user maunya cleanup hanya berdasar posisi aktif saja

Perbaikan:

- orphan cleanup sekarang hanya mempertahankan protection order jika symbol masih punya:
  - tracked DB position status `open` / `pending`, atau
  - live exchange position
- `openOrders` tidak lagi dipakai untuk memblok cleanup orphan TP/SL

Impact:

- kasus seperti `FLOCKUSDT` yang sudah tidak punya posisi, tapi masih punya TP/SL sisa, sekarang akan ikut dibersihkan walaupun exchange masih mengembalikan open order biasa pada symbol yang sama
- ini mencegah sampah protection lama mengganggu posisi future di coin yang sama

Tests added:

- `server/src/lib/orphan-cleanup-monitor.test.ts`
- update `server/src/lib/agent/tooling/position-ops-implementations.test.ts`

Kedua test memastikan orphan TP/SL tetap dibersihkan meskipun ada `open order` biasa dengan symbol yang sama, selama tidak ada tracked/live position.
