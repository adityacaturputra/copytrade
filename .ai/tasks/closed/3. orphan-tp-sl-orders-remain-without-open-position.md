## Resolution

Bug source:

- orphan cleanup cron in `server/src/lib/orphan-cleanup-monitor.ts`
- tool `cleanup_orphan_protection_orders` in `server/src/lib/agent/tooling/position-ops-implementations.ts`

Both previously still treated `exchange.getOpenOrders()` as a signal that a symbol was still active.

That is incorrect for orphan TP/SL cleanup, because:

- TP/SL or algo protection orders can themselves appear as open orders on the exchange
- the existence of a regular pending/open order with the same symbol does not mean the old protection orders are still valid
- the desired behavior is to decide cleanup only from active positions

Fix:

- orphan cleanup now keeps protection orders only if the symbol still has:
  - a tracked DB position with status `open` / `pending`, or
  - a live exchange position
- `openOrders` is no longer used to block orphan TP/SL cleanup

Impact:

- cases like `FLOCKUSDT`, where there is no remaining position but old TP/SL orders still exist, will now be cleaned up even if the exchange still returns regular open orders for the same symbol
- this prevents old protection-order garbage from affecting future positions on the same coin

Tests added:

- `server/src/lib/orphan-cleanup-monitor.test.ts`
- updates in `server/src/lib/agent/tooling/position-ops-implementations.test.ts`

Both tests ensure orphan TP/SL orders are still cleaned even when there is a regular open order for the same symbol, as long as there is no tracked or live position.
