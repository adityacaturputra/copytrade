## Context

This feature exists for exchange minimum order value cases, especially Bybit's `minimum order value 5 USDT`, when the result of `riskPerTradePercent` sizing is too small to pass the exchange minimum notional.

Main goals:

- keep using margin-based sizing in USDT, instead of forcing the user to think in notional terms
- auto-raise quantity only when it is explicitly allowed
- define a safe upper bound for auto-raise using `max margin` in USDT
- keep override precedence as `global -> account -> channel`
- allow channel override to force `ON` even if account-level is `OFF`

## Decision

Two new settings are used:

- `autoRaiseMinOrderEnabled`
- `autoRaiseMinOrderMaxMarginUsdt`

These settings are available in:

- global risk settings
- account risk overrides
- channel risk overrides

## Override Semantics

### `inherit`

Use the parent setting.

- at account level: parent = global
- at channel level: parent = account, then fallback to global if account is also not set

### `enabled`

Force the auto-raise minimum order feature to be active at that level.

If that level also defines `autoRaiseMinOrderMaxMarginUsdt`, then that level's margin cap is used.

### `disabled`

Force the auto-raise minimum order feature to be inactive at that level.

That means even if the parent is `enabled`, this level still rejects auto-raise.

## Effective Precedence

Evaluation order:

1. Global default
2. Account override
3. Channel override

Examples:

- Global `ON $0.50`, Account `inherit`, Channel `inherit` -> final result `ON $0.50`
- Global `OFF`, Account `enabled $0.40`, Channel `inherit` -> final result `ON $0.40`
- Global `ON $0.50`, Account `disabled`, Channel `inherit` -> final result `OFF`
- Global `ON $0.50`, Account `disabled`, Channel `enabled $0.30` -> final result `ON $0.30`

## Runtime Behavior

Before submitting an order to the exchange, the executor:

1. reads `InstrumentSpecs`
2. reads the exchange `minNotional` when available
3. checks whether `qty * price` is still below the minimum notional
4. if below minimum and auto-raise is enabled, it raises qty only up to the allowed `max margin` cap
5. if the required raise exceeds the cap, the trade is rejected instead of oversizing
